# Ілюстративні числа й твердження без першоджерела (Тема 11)

Цей файл фіксує твердження й цифри з навчального матеріалу, які є **ілюстративними прикладами** та не мають прямого підтвердження першоджерелом або верифікованим бенчмарком. Це **не означає, що вони хибні** — але їх слід використовувати як концептуальні ілюстрації, а не як задокументовані факти.

---

## 1. «300 інтеграцій замінено на 30 MCP-серверів» (Block/Square)

> «Якщо у Block було 10 різних AI-моделей і 30 внутрішніх систем, це потенційно означало 300 різних інтеграцій. MCP дозволив замінити їх на 30 серверів.»

**Статус:** ілюстративний приклад. Anthropic публічно підтверджує, що Block була раннім адоптером MCP. Конкретні цифри (300 → 30) та часовий виграш (місяці → дні) — гіпотетична ілюстрація масштабу проблеми, а не верифіковані дані Block.

**Джерело:** [Anthropic про ранніх адоптерів MCP](https://www.anthropic.com/news/model-context-protocol)

---

## 2. «$10 → $0,50 за годину роботи агента» (економія токенів)

> «Агент, який раніше коштував $10 за годину роботи через величезне споживання токенів, тепер може коштувати $0,50.»

**Статус:** ілюстративна оцінка без посилання на джерело. Реальна вартість залежить від:
- Конкретної моделі та провайдера
- Типу задачі та обсягу даних
- Архітектурних рішень (progressive discovery, code execution)
- Частоти та обсягу викликів

Загальна ідея про зниження вартості через менше токенів — правдоподібна, але конкретні цифри є ілюстративними.

## 3. «98,7% економія токенів» (150 000 → 2 000)

> «Зменшення використання токенів до 98,7% — реальні цифри з продакшену.»

**Статус:** цифра взята з демонстрації Anthropic про підхід code execution. Це результат **конкретного сценарію** (обробка великого датасету з агрегацією), а не середній показник по всіх задачах. Конспект це уточнює в розділі 4.8.

**Джерело:** [LinkedIn пост про Anthropic Code Execution](https://www.linkedin.com/posts/sarahstringerdeaton_the-mcp-code-execution-posts-from-anthropic-share-7394859348595724288-uf_U/)

## 4. «Менше ніж за годину» — інтеграція з GitHub

> «Після налаштування MCP в Claude Desktop створення інтеграції з GitHub заняло менше години.»

**Статус:** цей приклад Anthropic демонстрував публічно як демо. Однак «менше години» стосується **простої демонстраційної інтеграції** (GitHub MCP server + базові операції), а не повноцінної production інтеграції. Складні кейси займають більше часу.

## 5. Кейс Block — бухгалтерська автоматизація

> «AI-агент через MCP автоматично порівнює дані, категоризує транзакції, показує бухгалтеру лише ті випадки, де є розбіжності.»

**Статус:** ілюстративний workflow. Підтверджено: Block використовує MCP. Не підтверджено: описаний конкретний workflow бухгалтерської автоматизації як реалізований у production.

---

## 6. Кейс Box — workflow Box → Salesforce → Jira

> «Агент-аналізатор Box → агент CRM Salesforce → агент задач Jira → агент аналітики.»

**Статус:** концептуальний приклад workflow. Box має A2A API для роботи з AI-агентами та документами — це підтверджено. Конкретний описаний multi-agent workflow між Box, Salesforce та Jira як реалізована production-система — не підтверджено публічними джерелами.

## 7. Кейс Tyson Foods + Gordon Food Service — деталі договорів

> «Агент Tyson: є 7 тонн зараз, ще 5 тонн будуть у четвер. Ціна X. Агент Gordon: Бронюю 7 тонн + 3 тонни з четвергової партії.»

**Статус:** цей сценарій є деталізованою ілюстрацією реального пілоту. Google Cloud підтверджує спільний пілотний проєкт Tyson Foods та Gordon Food Service для обміну даними через AI-агентів. Однак описаний діалог і конкретний процес автоматичного бронювання є авторською ілюстрацією принципу, а не документальним описом пілоту.

**Джерело:** [Gordon Food Service — Google Cloud Case Study](https://cloud.google.com/customers/gordonfoodservice)

## 8. «Python 3.12+» як вимога для A2A SDK

> «Основна вимога — Python версії 3.12 або вище.»

**Статус:** оригінальна лекція вказує 3.12+, але офіційний A2A Python SDK підтримує Python **3.10+**. У конспекті виправлено на 3.10+. Перевіряйте актуальну документацію SDK при встановленні, оскільки вимоги можуть змінюватися.

---

## 9. «Google надає офіційні SDK»

> «Для роботи з A2A-протоколом розробники можуть використовувати офіційні SDK від Google.»

**Статус:** Google ініціював A2A, але наразі протокол розвивається як **відкритий стандарт** зі спільнотою та технічним керівним комітетом. SDK підтримується проєктом `a2aproject` (незалежна організація на GitHub), а не виключно Google. У конспекті це уточнено.

> «12 березня 2026 року вийшла стабільна версія A2A 1.0.»
